# v0.8 迭代记录：发布前工程收口

> 日期: 2026-11-08
> 范围: 不引入新功能，只处理依赖安全、质量门禁、类型债务、可维护性与发布口径。
> 验收口径: `uv run pytest -q`、`uv run python -m evals`、Ruff、格式化、类型棘轮、规模门禁、`openspec validate --specs/--changes`、`uv audit --locked`、`release_check.py` 与 `git diff --check` 全部通过。

## 背景

v0.7.0 发布后，功能范围保持不变，但积累了三类待收口事项：

1. 依赖审计报告 36 条已知漏洞（集中于 `mcp` / `pyjwt` / `certifi` / `opentelemetry-api`）；
2. CI 门禁缺少依赖审计与 OpenSpec 变更校验，覆盖率下限仍是 80%；
3. 类型债务 22 个、Ruff 规则集过窄、部分生产文件接近 300 行上限、文档基线漂移。

本轮按 P0 ~ P3 四个优先级依次处理。

## 已知限制

- 正式 TUI schema v2 基线仍需 Linux CI artifact 与人工复核；macOS 观测不能替代。
- `B904`、`SIM105`、`SIM102`、`B905`、`UP04x` 等需人工判断的 Ruff 子规则尚未纳入。
- 默认沙箱策略仍为 `danger-full-access`，插件目录放置即信任并在同进程执行；这属于产品/安全决策，本轮只补齐文档说明。
- 工作区合并、跨进程恢复、长期记忆、费用估算与 Web UI 仍不在范围内。
