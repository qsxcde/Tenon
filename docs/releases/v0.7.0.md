# v0.7.0 发布说明

> 发布日期：2026-10-24
> 上一发布版本：v0.5.0（2026-10-10）
> 运行时要求：Python 3.12+、`uv`；本版本同时包含 v0.6 正确性硬化的全部修复

## 摘要

v0.7 的主题是**可扩展性与运行期安全**。项目从"固定八工具的串行只读 Agent"扩展为可插件化、可并行委派、可选择进程边界、可回退工作区写入的运行时：

- **工具层可扩展**：工具注册表数据化，新增 `web_fetch` / `web_search` / `todo`，内建工具由 8 个增至 11 个；新增用户插件目录（v1 仅贡献工具）。
- **执行管线可组合**：工具执行由单点钩子改为有序瀑布链（通知 / 改参 / 门禁 + 结果变换），安全策略固定链尾。
- **多 Agent 更强**：Subagent 支持有界并发（默认仍串行），新增 `implement` 受限可写 profile。
- **运行期更安全**：三档 bash 沙箱；`write` / `edit` 写前自动快照，`codeagent undo` 逐级回退。
- **可验证**：缓存命中诊断、稳定前缀契约、离线端到端评测套件纳入 `contract` 门禁。

## 新增能力

### 工具与注册表

- 内建工具固定为十一个，声明顺序即装配顺序：`read`、`write`、`edit`、`bash`、`grep`、`find`、`ls`、`skill`、`web_fetch`、`web_search`、`todo`。
- `make_tools` 由硬编码列表改为声明式 `ToolSpec` / `ToolRegistry`；契约测试锁定名称、类型与顺序，新增工具只需追加声明。
- `web_fetch`：仅接受 http/https（拒绝 `file://` 等），网络经注入实现（缺省 urllib，响应读取 ≤ 2 MB），输出统一治理并携带完整性事实；出站调用进入确认环。
- `web_search`：搜索提供方由组合根注入（缺省未配置时返回明确不可用提示并指引 `web_fetch`，不伪造结果），`limit` 缺省 5；出站调用进入确认环。
- `todo`：整体替换式会话级任务清单（pending / in_progress / done），条目上限 200、id 必须唯一；仅驻内存，不进入会话持久化格式。
- Skill 适配器的能力声明（web / todo / 各工具）改为由注入的工具名派生，消除手工维护的失同步。

### 工具执行瀑布管线

- `before_tool_calls`：有序链，单个钩子可返回 `None`（通知继续）、`ToolCall`（改参，后续钩子与执行只见新参数）、`ToolDecision.block`（门禁短路：不执行工具、不跑 post 链）、`ToolDecision.allow(warning=True)`（放行并累积警告）。
- `after_tool_calls`：有序链，返回 `None` 保留当前结果，返回 `ToolResult` 则替换并传给下一钩子（可用于脱敏）。
- 安全策略门禁固定位于链尾，`decide` 与确认事件都基于改参后的调用。
- 多条警告合并为单个 `[安全提示]` 前缀行，保持可按行剥离。
- 钩子返回非法类型时抛出明确错误（fail-closed），不会把坏钩子静默当成放行。

### 扩展插件目录（v1）

- 目录：`~/.codeagent/extensions/<目录>/codeagent-plugin.json`，字段 `id` / `name` / `version` / `module` / `tools`。
- 插件模块导出 `TOOL_SPECS`（与内建 `BUILTIN_TOOL_SPECS` 同构），工具名强制命名空间 `ext__<插件id>__<工具名>`。
- `id` 与工具名需匹配 `^[a-z][a-z0-9_]*$` 且不含 `__`；`module` 解析后必须仍在插件目录内。
- 单插件失败（manifest 非法、import 异常、导出缺失、id 冲突）只产生 `plugin_failed:` 诊断并跳过，不阻塞其它工具装配。
- 信任模型为**目录放置即信任**（与 `mcp.json` 列出即启动进程一致）；调用层 fail-closed：`ext__*` 默认需确认，可在 `~/.codeagent/extensions.json` 用 `permissions.deny/ask/allow` 显式放行或拒绝（glob，deny > ask > allow，与 MCP 规则同源）。

### Subagent

- `subagent_max_concurrency`（默认 1）控制并发槽位：1 保持原有串行语义，>1 启用有界并发；准入顺序、预算、取消、终态归因与有界清理不变。
- 新增 `implement` profile：可使用 `read` / `write` / `edit` / `bash` / `grep` / `find` / `ls` / `skill`，但禁止 `delegate` 与 MCP 工具；深度仍固定为 1。
- `explore` / `review` 保持只读；profile 校验 fail-closed（只读 profile 含写工具、可写 profile 工具集不一致都会在装配期报错）。

### 模型层

- 新增 API 形状注册表：`ProviderDefinition.api_shape` 声明线上协议形状（默认 `openai-completions`），未知形状在构造注册项时即失败，不静默回退。
- 新增 `register_provider` / `register_api_shape` 入口：同形状 provider 无需修改 transport；重复 provider id 或形状名拒绝，且不覆盖内置项。

### 运行期安全

- 三档 bash 沙箱：`read-only` / `workspace-write` / `danger-full-access`（默认）。macOS 使用 `sandbox-exec`（Seatbelt），Linux 使用 `bwrap`；后端参数以独立 argv 元素注入，不拼接进 shell 命令。
- 受限策略在无可用后端时 fail-closed：拒绝执行并给出包含平台、策略与安装指引的错误，不静默降级。
- `write` / `edit` 在路径锁内、实际写入前保存原文快照到 `~/.codeagent/checkpoints/`（再次写入前不存在则记录"不存在"）；快照条数上限 200，超出淘汰最旧。
- `codeagent undo`：`--list` 列出最近快照、`--dry-run` 预览、无参数执行 LIFO 恢复（恢复一次消耗一条）；快照失败不阻塞正常写入。

### 诊断与评测

- `--context` 输出缓存命中率与诊断码（`cache_unknown` / `cache_cold` / `cache_effective`），样本不足时不猜测。
- 新增易变前缀检测（ISO 时间戳、临时目录），并用契约测试锁定基础系统提示词前缀不含易变标记。
- 新增离线评测框架：`uv run python -m evals`，用 fake 模型驱动真实 Agent 循环，覆盖工具流、未知工具、审批阻断、改参传播四类行为；`tests/test_evals.py` 将其纳入 `contract` 门禁。
- 审批结果收敛为封闭枚举 `ApprovalOutcome`（`allowed_once` / `rejected` / `cancelled` / `timed_out` / `unavailable`），仅放行态可执行，其余终态一律拒绝并带可诊断原因。

## 修复（随 v0.7.0 一并交付的 v0.6 硬化）

- 安全分类器可被包装器前缀绕过（`timeout` / `nice` / `env` / `xargs` / `command` / `bash -lc` 等）与命令替换（`$(rm -rf ~)`）绕过。
- 敏感路径判定误杀正常动作（`echo secret`、`grep -r SECRET src`、`cat .env.example`）；`.env.example` 等模板文件恢复放行。
- 只读搜索工具（`grep` / `find` / `ls`）此前没有文件边界，可绕过 `read` 读取界外敏感路径；现在与 `read` 共用同一边界结论。
- 越界警告此前模型不可见；现在以 `[安全提示]` 前缀进入模型可见的工具结果。
- bash 合并输出此前可达约 60 KB；现在按有效上限二次截断并标记 `truncated_by=merged_budget`。
- 中文 token 被系统性低估约 4 倍；新增共享估算器（CJK 按字计价），预算与压缩切点共用实现。
- `prepare_context` 重复发布 `CONTEXT_BUDGET` 事件；现在每个请求恰好一个预算快照。
- 会话索引追加退化为 O(n²)（1000 次追加约 7s → 0.37s）。

## 破坏性变更

| 变更 | 影响面 | 迁移方式 |
|---|---|---|
| `AgentLoopConfig.before_tool_call` / `after_tool_call` 改名为 `before_tool_calls` / `after_tool_calls`，类型为元组 | 直接构造 `AgentLoopConfig` 的集成代码与测试 | 单个回调用 `(hook,)` 包装 |
| `RuntimeExtensions.before_tool_call` / `after_tool_call` 同上 | 使用组合根扩展结构的代码 | 同上 |
| `ConfirmationRequest.status`（开放字符串）改为 `outcome: ApprovalOutcome \| None` | 读取确认请求状态的 UI / 集成代码 | 改用 `outcome` 封闭枚举 |
| 内建工具数量 8 → 11 | 断言工具数量或白名单的集成代码 | 更新期望集合；`allowed_tool_names` 语义不变 |
| `provider_id="minimax"` 的配置类名 | 直接引用配置类名的代码 | 使用 `MiniMaxConfig`（注册表键名未变） |

## 默认行为不变

未显式配置时，以下行为与 v0.5.0 一致：沙箱为 `danger-full-access`、Subagent 并发为 1（串行）、审批 `ask` 在 headless 下仍然拒绝、既有八工具行为与会话持久化格式未变。`write` / `edit` 会新增写前快照文件（不影响写入结果与错误语义）。

## 已知限制

- 插件与内建工具同进程执行（目录放置即信任）；沙箱只约束 bash 子进程，不约束插件 Python 代码。插件 v1 为单文件模块，不支持兄弟 import，且仅能贡献工具。
- `workspace-write` / `read-only` 依赖平台后端（macOS `sandbox-exec`、Linux `bwrap`）；缺失时受限策略直接拒绝执行。
- checkpoint 是全局 LIFO 回退，不绑定会话或轮次，也不覆盖 `bash` 写入的文件。
- 缓存能力止于观测与稳定前缀保护，provider 侧缓存开关不在本层控制。
- Web UI、跨进程恢复、长期记忆、费用估算与工作区合并仍不在范围。
