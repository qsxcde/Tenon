# v0.7.0 升级指南

> 适用：从 v0.5.0（或未发版的 v0.6 工作树）升级到 v0.7.0
> 预计无需数据迁移；配置向后兼容，破坏性变更仅影响直接构造 core 配置或读取确认状态的集成代码

## 1. 升级路径

- **v0.5.0 → v0.7.0**：直接升级。会话 JSONL 格式、provider 配置、技能包与 MCP 配置均未改变。
- **未发版 v0.6 → v0.7.0**：直接升级，同时获得 v0.6 的正确性修复。
- **低于 v0.5.0**：请先升级到 v0.5.0 并完成其迁移，再执行本指南。

## 2. 升级前检查

1. 确认工作区干净或已提交：`git status`；避免升级覆盖本地未提交改动。
2. 备份用户配置目录（含会话、技能包与新增的 checkpoint）：
   ```bash
   cp -a ~/.codeagent ~/.codeagent.bak-$(date +%Y%m%d)
   ```
3. 确认 Python 3.12+ 与 `uv` 可用：`uv --version`、`python3 --version`。
4. 若使用 `workspace-write` / `read-only` 沙箱，先确认后端可用：
   - macOS：`which sandbox-exec`（系统自带）
   - Linux：`which bwrap`；缺失时安装 `bubblewrap`（Debian/Ubuntu：`apt install bubblewrap`）

## 3. 升级步骤

```bash
# 1) 取得新版本代码或安装包
git fetch --tags && git checkout v0.7.0        # 或按发布渠道安装

# 2) 同步依赖（保持 lock 文件一致）
uv sync --locked --group dev                   # 开发环境
uv sync --locked                               # 仅运行

# 3) 冒烟验证
uv run codeagent --prompt "你好"                # 无头 CLI
uv run codeagent --tui                          # 交互式 TUI
```

## 4. 配置变更

新增配置项（写入 `~/.codeagent/.env`，键名不带前缀，大小写不敏感）：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `SANDBOX_POLICY` | `danger-full-access` | bash 执行边界：`read-only` / `workspace-write` / `danger-full-access` |
| `SUBAGENT_MAX_CONCURRENCY` | `1` | 子 Agent 并发槽位；1 = 串行，≥2 启用有界并发 |
| `CHECKPOINTS_ENABLED` | `true` | 是否在 `write` / `edit` 前记录文件快照 |

建议：

- 先保持默认（行为与 v0.5.0 一致），确认基线后再逐步收紧到 `workspace-write`。
- 启用并发前确认模型配额与工具副作用可接受；并发写同一文件由进程级路径锁串行化，但多子 Agent 仍可能产生语义冲突。
- 若磁盘空间紧张，可关闭 `CHECKPOINTS_ENABLED`，或定期清理 `~/.codeagent/checkpoints/`（上限 200 条会自动淘汰最旧）。

## 5. 破坏性变更迁移

### 5.1 工具钩子字段改名（core 集成代码）

```python
# v0.5：单值字段
config = AgentLoopConfig(
    model=model,
    before_tool_call=my_hook,
    after_tool_call=my_post_hook,
)

# v0.7：有序元组
config = AgentLoopConfig(
    model=model,
    before_tool_calls=(my_hook,),
    after_tool_calls=(my_post_hook,),
)
```

`RuntimeExtensions` 同步改名。钩子返回值语义：

| 返回 | 含义 |
|---|---|
| `None` | 通知，继续链 |
| `ToolCall` | 改参，后续钩子、策略门禁与执行只见新参数 |
| `ToolDecision.block(reason)` | 门禁短路：不执行工具、不跑 post 链 |
| `ToolDecision.allow(reason, warning=True)` | 放行并按序累积警告 |
| 其它类型 | 抛出 `TypeError`（fail-closed） |

`after_tool_calls` 钩子返回 `None` 保留当前结果，返回 `ToolResult` 则替换并传给下一钩子。

### 5.2 确认请求终态

```python
# v0.5：开放字符串
if request.status == "approved": ...

# v0.7：封闭枚举
from codeagent.core.contracts.ports import ApprovalOutcome

if request.outcome is ApprovalOutcome.ALLOWED_ONCE: ...
```

仅 `ALLOWED_ONCE` 可执行；`rejected` / `cancelled` / `timed_out` / `unavailable` 一律拒绝。headless 下 `ask` 映射为 `unavailable` 并拒绝，语义与 v0.5 一致。

### 5.3 工具集合

内建工具由 8 个增至 11 个（新增 `web_fetch` / `web_search` / `todo`）。断言工具数量或名称集合的测试/集成代码需更新；`allowed_tool_names` 过滤语义不变，插件工具名也可被白名单过滤。

### 5.4 Provider 注册

`ProviderDefinition` 新增 `api_shape`（默认 `openai-completions`，未知形状在构造时失败）。自定义 provider 推荐改用注册入口：

```python
from codeagent.ai.providers import ProviderDefinition, register_provider

register_provider(ProviderDefinition(provider_id="my-gateway", factory=make_llm))
```

重复 provider id 会被拒绝，内置项不可覆盖。

## 6. 新目录与文件

| 路径 | 用途 | 是否需纳管 |
|---|---|---|
| `~/.codeagent/extensions/<id>/` | 用户插件目录（放置即信任） | 用户自管；不要提交到代码仓库 |
| `~/.codeagent/extensions.json` | 插件工具权限规则（可选） | 用户自管 |
| `~/.codeagent/checkpoints/` | 写前快照（`index.jsonl` + `*.bak`） | 用户自管；可清理 |

插件最小示例：

```text
~/.codeagent/extensions/demo/
├── codeagent-plugin.json
└── plugin.py
```

```json
{ "id": "demo", "name": "Demo", "version": "0.1.0", "module": "plugin.py", "tools": ["hello"] }
```

```python
# plugin.py
from pydantic import BaseModel

from codeagent.tools.base import AtomicTool
from codeagent.tools.registry import ToolSpec


class HelloArgs(BaseModel):
    name: str = "world"


class HelloTool(AtomicTool[HelloArgs]):
    name = "hello"
    description = "say hello"
    Args = HelloArgs

    def _invoke(self, args):
        return f"hello {args.name}"


TOOL_SPECS = (ToolSpec("hello", lambda context: HelloTool(cwd=context.cwd)),)
```

插件工具以 `ext__demo__hello` 注册，默认需确认。显式放行：

```json
{ "permissions": { "allow": ["ext__demo__*"], "deny": [], "ask": [] } }
```

## 7. 行为变化清单（用户视角）

- **web 工具需确认**：`web_fetch` / `web_search` 属网络出站，进入 `ask` 档；无头模式（无确认通道）默认拒绝，可用 `--yes` 显式放行。
- **插件工具默认需确认**：未配置 `extensions.json` 时同样在无头模式下拒绝。
- **`implement` 子 Agent 可写**：仅当显式请求该 profile 时生效；子 Agent 仍遵守安全策略与确认环，且不能继续委派。
- **写前快照**：`write` / `edit` 会在用户目录留下快照文件；写入结果、输出与错误语义不变。
- **`--context` 输出更丰富**：新增缓存命中率与冷/暖诊断码，原有字段保留。
- **技能 bootstrap 提示更新**：能力声明中 todo / web 变为可用，模型不再被告知"当前不可用"。

## 8. 升级后验证清单

```bash
uv run codeagent --prompt "列出当前目录"                  # 基本运行
uv run codeagent --context --prompt "你好"               # 缓存诊断输出
uv run codeagent undo --list                             # checkpoint 入口可用
uv run python -m evals                                   # 离线评测 4/4
uv run pytest -m "unit or contract" -q --strict-markers   # 1718 passed
```

若启用沙箱：在 `workspace-write` 下执行 `uv run codeagent --prompt "写一个文件到 /tmp 之外的系统目录"`，应收到明确的拒绝诊断而非静默成功。

## 9. 回滚

1. 停止正在运行的 codeagent 进程。
2. 恢复代码与依赖：`git checkout v0.5.0 && uv sync --locked`（或重新安装 v0.5.0）。
3. 如需恢复用户目录：`mv ~/.codeagent ~/.codeagent.v07 && mv ~/.codeagent.bak-<日期> ~/.codeagent`。
4. 注意：v0.7 写入的 checkpoint 与插件目录对 v0.5 无副作用，可保留；会话 JSONL 未变更，无需迁移。

## 10. 常见问题

**`web_search` 返回"不可用"？**
未注入搜索提供方。直接使用 `web_fetch` 抓取已知 URL，或在组合根注入 `searcher`。

**插件工具一调用就被拒绝？**
无头模式没有确认通道，且 `ext__*` 默认 `ask`。在 `~/.codeagent/extensions.json` 中加入 `allow` 规则，或使用 `--yes`。

**`workspace-write` 报"沙箱策略无法执行"？**
当前平台缺少后端。macOS 检查 `sandbox-exec`，Linux 安装 `bubblewrap`；或临时改回 `SANDBOX_POLICY=danger-full-access`。

**`undo` 找不到刚才的写入？**
快照只覆盖 `write` / `edit`，不覆盖 `bash` 写文件；且为全局 LIFO，仅保留最近 200 条。

**子 Agent 并发开启了但没有并行？**
确认 `SUBAGENT_MAX_CONCURRENCY ≥ 2`，且父 Agent 确实发起了多个 `delegate` 调用。
